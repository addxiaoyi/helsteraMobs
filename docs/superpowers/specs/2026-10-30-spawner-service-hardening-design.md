# SpawnerService 加固设计

## 目标

逐行审查并加固 `helstera-ai/src/main/java/dev/helstera/ai/spawner/SpawnerService.java`，优先降低最近新增的成组生成、间隔抖动、光照门控和失败路径的不确定性；保持现有配置与公开 API 兼容，不扩展新的 MythicMobs 功能。

## 范围

本阶段只修改 `SpawnerService` 及其单元测试：

- 覆盖 `group-size`、`interval` 区间、`interval-jitter` 和 `cooldown-jitter` 的异常输入与边界。
- 验证成组生成仍逐只遵守 `max-alive`、`max-per-world`、`max-per-player` 等已有上限。
- 验证生成回调返回失败或抛出异常时，生成计数、冷却和状态不会被错误推进。
- 验证未知世界、未加载区块和其他生成前置条件继续采用 fail-closed 行为。
- 保留现有默认值、ID 大小写不敏感和旧配置兼容行为。

不在本阶段修改严格 Paper 验证脚本、Custom Menu、其他模块或临时探针文件。

## 设计

### 配置解析

配置解析继续在加载期完成。整数区间只接受整数端点，反向区间归一化，非法值采用当前项目既有的安全默认策略并记录问题；小数不会被静默截断为有效的成组数量。抖动支持比例和百分比写法，最终限制在 `0..1`，超范围保留问题记录并钳制，非有限值不得进入运行期计算。

### 生成上限

一次成组生成只是多次普通生成尝试的组合，不拥有绕过上限的特殊路径。每只实体都要经过现有存活数、世界数和玩家数限制；达到任一限制后停止本组剩余尝试。

### 失败状态

生成回调返回失败或抛出异常时，该只不计入 `totalSpawned`，不推进成功生成计数，也不提前写入成功冷却状态。异常应被隔离并记录，不能使调度线程或其他刷怪点失效。

### 世界与区块门控

世界解析失败、区块未加载或光照条件无法确认满足时拒绝生成。不得把不可确认状态当作允许生成。

## 测试计划

先新增可独立失败的回归测试，再修改实现。测试覆盖：

1. `parseRange` 的整数、反向、空值、非法文本和小数输入。
2. 抖动比例、百分比、超范围和非有限输入。
3. 成组规模与存活上限的交互。
4. 生成回调失败和抛异常后的计数/冷却状态。
5. 未知世界、未加载区块和光照门控的拒绝行为。
6. 既有默认值、大小写不敏感 ID 和兼容配置不回归。

验证命令：

```bash
mvn -o -Dmaven.repo.local=C:/Users/l/.m2/repository test -Dfile.encoding=UTF-8
```

成功标准：新增回归测试通过；全量 Maven 测试退出码为 `0`；工作区不把 `.codegraph/`、`.dsh-*`、探针、日志或构建产物加入提交。
